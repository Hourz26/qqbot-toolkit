## 三、踩过的坑与修复

### 坑 1：DSH 2.0.18 改了路径，`dsh` 命令失效

旧入口 `host-commands\desktop\bin\dsh.cmd` 指向 `resources\app.asar\lib\desktop-cli.js`（已不存在），新路径是 `resources\app\lib\desktop-cli.js`。

**修复**：自建 `D:\Apps\snowluma\dsh-shim.cmd`，内容指向新路径。bridge.mjs 用它。

### 坑 2：SnowLuma 配置文件直接改会被回写

`config/onebot_*.json` 是快照，退出时会用内存配置覆盖。

**正确做法**：走 API `POST /api/config/<uin>`，body 就是配置对象本身。

### 坑 3：SnowLuma API 的 POST body 不能套 `{config: ...}`

前端是 `postJson(url, t)`，`t` 就是配置对象。多套一层不生效。

### 坑 4：aiocqhttp 的 WS 路径与鉴权

- 路径是 `/ws`（不是 `/onebot/v11/ws`）
- 需要 `Authorization: Bearer <token>` + `X-Client-Role` + `X-Self-ID` 头
- 手动用 query 参数探测会得到 401，是正常的

### 坑 5：PowerShell 发中文变问号

`Invoke-WebRequest` 用 ISO-8859-1 编码，中文会变 `??`。

**修复**：发 QQ 消息一律走 MCP（`mcp__snowluma__invoke_action`），不要用 PowerShell 拼 JSON。

### 坑 6：SnowLuma 挂错账号（主号被 hook）

重启后自动挂载会选先出现的 QQ 进程，可能是主号。

**修复**：watchdog 加账号校验，发现非小号就 `unload` 再挂小号。已实测通过（含竞态场景）。

### 坑 7：AstrBot 白名单空但启用 → 消息被静默丢弃

`enable_id_white_list: true` 且 `id_whitelist: []`，所有消息被拦。

**修复**：关闭白名单（`enable_id_white_list = false`），或填入允许的 QQ 号。

### 坑 8：HuggingFace 镜像不可用

`hf-mirror.com` 超时，反而 `huggingface.co` 直连正常（155ms）。

**结论**：别设 `HF_ENDPOINT` 镜像。

### 坑 9：PM2 命令间歇性卡住

`pm2 stop/start/restart` 偶尔 5 分钟不返回（一次 `restart snowluma` 也卡过）。

**应对**：卡住时直接 kill 进程让 PM2 自动重启，或等它自己恢复。

### 坑 10：账号与数据目录错位（**未修复**）

| 进程 | 数据目录 | 登录账号 |
|---|---|---|
| PID 25344 | `Roaming\QQ`（主目录） | **小号** 3799652874 |
| PID 31680 | `Local\QQ-SnowLuma`（隔离） | **主号** 3351763568 |

当前能用（SnowLuma 挂小号、主号未被注入），但隔离意义已失效。

**建议手动纠正**：主 QQ 退小号登主号；隔离实例登小号。
